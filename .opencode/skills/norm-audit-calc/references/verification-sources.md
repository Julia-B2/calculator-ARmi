# Верификация нормативных документов

Порядок: первоисточник → авторитетная база → только потом правка `norms.json`.

## Источники по типам документов

| Документ | Где читать | Примечание |
|---|---|---|
| СП, ГОСТ (СП 42, СП 54, СП 59, СП 113, СП 158, ГОСТ Р 52941) | `docs.cntd.ru/document/<id>/titles/<section>` | **Только браузер.** Из node — `fetch failed` (TLS). Читать `innerText` блока `.document-page` через `browser.evaluate` |
| ПП Москвы (945-ПП, 2150-ПП, 2151-ПП, 2152-ПП, 2118-ПП) | `base.garant.ru/<id>/`, `meganorm.ru/mega_doc/...`, `consultant.ru` | `meganorm.ru` местами отстаёт по редакциям — сверять с «Вестником Москвы»/docs.cntd |
| Официальные тексты Правительства Москвы | `mos.ru`, `mos.ru/upload/documents/files/...` (PDF) | PDF-таблицы — через OCR |
| Региональные акты субъектов (РНГП/МНГП) | сайты регионов, `consultant.ru` | Для регионов без подтверждённого акта — значение помечается «справочно, уточнить по РНГП региона» |

## Технические приёмы

- **Браузер для docs.cntd.ru**: `browser.tabs.open({url})` → `browser.evaluate({tabID, script})`
  с `document.querySelector('.document-page').innerText`. В code mode `setTimeout`
  недоступен — использовать ожидание загрузки вкладки.
- **node-fetch** для garant/consultant/meganorm/mos.ru: `NODE_TLS_REJECT_UNAUTHORIZED=0`,
  User-Agent браузера. `webfetch` в этой среде возвращает 403/Transport error — не использовать.
- **Очистка HTML** перед grep: снять `script/style`, заменить теги на пробелы,
  разворачивать `&nbsp;`, `&#8201;`, `&quot;`.
- **Таблицы-картинки**: `ocr.space` (`apikey=helloworld`, `language=rus`, `OCREngine=2`);
  после OCR обязательно сверить легенду (обозначения величин) с текстом акта.
- **Поиск**: DuckDuckGo в браузере; запрос с несколькими кавычками даёт пустую выдачу —
  использовать простые запросы. `websearch` тоже работает.
- **PowerShell**: `$OutputEncoding=[Console]::OutputEncoding=[System.Text.Encoding]::UTF8`
  для кириллицы; сложный JS/JSON писать в файл и запускать `node file.js` (инлайн-код
  ломается кавычками).

## Что обязательно фиксировать

1. Документ, пункт (номер и заголовок), редакция (дата и номер изменения).
2. Само значение и единицы измерения.
3. URL-источник и дата проверки.
4. Статус: действующий / заменён / не применяется / требует уточнения.

## Проверки на «подмену редакции»

- Правило: «отклонение от таблицы» допустимо не автоматически — обоснование в пояснительной
  записке / расчётах к планировочным решениям; экспертиза проверяет убедительность и
  отсутствие нарушений иных норм.
- Если акт имеет приложения с «прим. 1…4» — применимость примечания проверять по тексту,
  а не по памяти.
- Числовые значения, встречающиеся в нескольких актах (например, 5,8 / 13,2 / 19
  посещений на 1000 жителей), искать источник целиком: они могут быть региональными
  (ПП № 2150-ПП), а не федеральными (СП 158) — и это меняет формулировку в калькуляторе.
