# Особенности среды и рабочие приёмы

Проверено на этой машине; команды даны для PowerShell.

## Файлы и пути

- Рабочая папка — UNC (`\\fs.kts.local\users\y.baranova\Для ИИ`). **node не читает UNC-путь
  через `require`** — копировать файлы в `%LOCALAPPDATA%\Temp\56\opencode` и работать там.
- Рабочие скрипты хранить в temp: `dump.js` (строки файла с номерами), `find.js` (поиск по
  регулярке), `fetch1.js` (загрузка URL в текст), `patch_norms.js` (программная правка
  norms.json).
- `git status` / `git diff --stat` — из корня репозитория; путь к проекту: `-- "Калькулятор АР"`.

## Node

- Версия: v24+. ESM-модули импортируются напрямую (`import ... from "./js/blocks/parking.js"`).
- Скрипты с аргументами: `node script.js <arg1> <arg2>`; JSON-аргументы — читать через
  `JSON.parse(process.argv[2])`.
- Для сравнения JSON с эталонным форматированием — `JSON.stringify(obj, null, 2)`; в
  `norms.json` часть объектов записана в одну строку, поэтому **точечные правки текстом
  дают меньший diff**, чем полная перезапись (восстановление: `git diff`).

## Python

- В системе `python` отсутствует; найден интерпретатор 3ds Max:
  `C:\Program Files\Autodesk\3ds Max 2023\Python\python.exe` (Python 3.9) — подходит для
  проверки синтаксиса (`-m py_compile`) и запуска `python/parking_calc.py`.
- `python/parking_calc.py` читает ту же `app/data/norms.json`; контрольный пример должен
  давать числа, совпадающие с JS-прогоном.

## Проверка в браузере

- `file://` браузеру недоступен — нужен локальный HTTP-сервер (node, ~15 строк) над копией
  `app/`, затем `browser.tabs.open("http://127.0.0.1:<port>/index.html")`.
- В `browser.evaluate` передаётся `{tabID, script}`; `setTimeout` в code mode недоступен.
- Полезно собирать в одном evaluate: выбор региона, установка полей, `click()` кнопки
  «Рассчитать», чтение таблиц результатов и `window.onerror` — так проверяется интерфейс
  целиком за один вызов.
- После проверки сервер и вкладки закрывать (`Get-Process node | Stop-Process`).

## Правила правки калькулятора

- Встроенная копия норм в `app/index.html` генерируется:
  `node tools/build-embedded-norms.mjs` (запись) и `--check` (проверка).
- Значения по умолчанию в полях — произвольные; данные образцов из корня проекта
  в интерфейс и в отчёты не переносятся.
- У каждого расчётного показателя — ссылка на пункт НД (`refPoint`).
