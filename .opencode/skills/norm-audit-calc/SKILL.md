# Аудит калькулятора по нормативным документам

Процедура применима к проекту `Калькулятор АР/` (папка приложения — `app/`, второй
движок — `python/`, генератор встроенной копии норм — `tools/`).

## 0. Правила, обязательные для этого проекта

1. **Сначала план и согласование.** До правок кода — короткий план (что проверяем, что
   меняем, где сохраняем результат) и подтверждение пользователя. Правки вносятся только
   после подтверждения; уточняющие вопросы задаются через `question`.
2. **Без домыслов.** Любое нормативное утверждение — со ссылкой на пункт документа и
   редакцию. Если источник не подтверждён — так и написать («не подтверждено, требует
   уточнения»), а не подставлять правдоподобное число.
3. **Образцы (docx/xlsx в корне «Калькулятор АР») не трогать.** Их значения не
   подставляются в калькулятор: значения по умолчанию — произвольные.
4. **Единый источник нормативов — `app/data/norms.json`.** Встроенная копия в
   `app/index.html` генерируется, а не правится руками:
   `node tools/build-embedded-norms.mjs` (проверка — `--check`).
5. **Ответ по-русски, по существу, структурно** (таблицы/списки), с итогом и перечнем
   открытых вопросов.

## 1. Инвентаризация

- Прочитать `Калькулятор АР/README.md`, `Калькулятор АР/Doc/` (ТЗ) и `app/data/norms.json`.
- Выписать структуру: `app/js/blocks/*` (расчёты), `app/js/main.js` (UI), `app/js/export/*`
  (выгрузки), `app/js/summary.js` (сводка), `app/js/utils.js`, `app/js/engine.js`,
  `python/parking_calc.py` (второй движок).
- Зафиксировать, какие поля читаются из `norms.json` в коде — после правки норм искать
  остаточные ссылки на старые ключи (`grep` по `reductionK`, `minSizes`, `afterF`,
  `flowPerElevator`, `СП 42.13330.2016` и т. п.).

## 2. Верификация нормативных документов

Порядок и адреса источников — `references/verification-sources.md`. Кратко:

- Тексты НД читать **только из первоисточников**: `docs.cntd.ru`, `base.garant.ru`,
  `consultant.ru`, `meganorm.ru`, `mos.ru`.
- `docs.cntd.ru` — **только через браузер** (`browser.tabs.open` + `browser.evaluate`);
  из node TLS-соединение не устанавливается.
- Таблицы, пришедшие картинкой (как в 945-ПП), читаются OCR: `ocr.space`
  (`apikey=helloworld`, `language=rus`, `OCREngine=2`) — результат сверять с легендой.
- Для каждого подтверждённого значения фиксировать: документ, пункт, редакцию, источник.
- Обязательно проверить **статус актуальности**: «действующая редакция» / «заменён» /
  «не применяется» (например, СП 42.13330.2016 заменён СП 42.13330.2026).

## 3. Headless-прогон расчётов (до и после правок)

- Копировать `app/js` и `app/data/norms.json` во временную папку (node не читает UNC-путь
  через `require`) и запускать блоки как ESM-модули:
  `import { calculateParking } from "./js/blocks/parking.js"`.
- Прогонять на **произвольных** данных (не на образцах), фиксировать числа до правок и
  после — числа обязаны сходиться между движками.
- Для полной проверки интерфейса — локальный HTTP-сервер + браузер (см.
  `references/toolchain.md`): расчёт, переключение методов, экспорт HTML/XLSX, отсутствие
  ошибок в консоли.

## 4. Внесение правок

Порядок (чтобы не разъехались источники):

1. `app/data/norms.json` — программно (node-скрипт с JSON.parse → правка → stringify),
   чтобы не плодить ручные расхождения; значения и ссылки сразу с `refPoint`.
2. Расчётные блоки (`app/js/blocks/*.js`) — формулы, округление, режимы, предупреждения.
3. `app/index.html` — новые поля ввода (произвольные значения по умолчанию!), подписи,
   пояснения; встроенная копия норм — только генератором.
4. `app/js/main.js` — связка UI ↔ движок, отображение новых полей и результатов.
5. Выгрузки (`app/js/export/*`, `app/js/summary.js`) — знаки, новые строки, `items`.
6. `python/parking_calc.py` — синхронизация второго движка с тем же `norms.json`.
7. `Калькулятор АР/README.md` — если изменились блоки, нормы или способы запуска.

Правила округления и ссылок: округление **итога** (не по строкам) — если это требует
НД; «отклонение от нормы» оформляется так, как предписывает НД (часто — как «расчёт по
ГОСТ/СП с обоснованием», а не как нарушение).

## 5. Проверка результата

- node-прогон блоков: числа совпадают с ожидаемыми, нет `NaN`/`undefined`.
- Браузерный прогон: расчёт без ошибок, новые поля работают, экспорт HTML и XLSX проходит.
- Паритет движков: `python/parking_calc.py` даёт те же числа, что JS (при наличии python).
- `node tools/build-embedded-norms.mjs --check` — встроенная копия актуальна.

## 6. СОХРАНЕНИЕ РЕЗУЛЬТАТА (обязательный шаг)

Результат сохраняется **файлом в `reports/`** — по образцу существующих отчётов:
`reports/YYYY-MM-DD_<краткая-тема>.md`.

Создать отчёт скриптом навыка (он подставит дату, заголовок и список изменённых файлов):

```bash
node .opencode/skills/norm-audit-calc/scripts/new-report.mjs "<краткая-тема>"
```

Затем заполнить шаблон (`templates/report-template.md`) по факту:

| Раздел отчёта | Содержание |
|---|---|
| 1. Предмет проверки | Объект/блоки, редакции НД, дата, режим проверки |
| 2. Нормативная база | Таблица: документ → пункт → подтверждённое значение → источник |
| 3. Расхождения | Таблица: пункт НД → как было → как стало → файл/строка |
| 4. Внесённые изменения | Список файлов и суть правки (по пунктам) |
| 5. Контрольные прогоны | Числа до/после, паритет движков, проверка в браузере |
| 6. Не подтверждено | Значения без источника, требующие решения пользователя |
| 7. Изменённые файлы | Вывод `git status`/`git diff --stat` |
| 8. Следующие шаги | Что сделать пользователю (коммит, уточнить нормы) |

Правила сохранения:

- Отчёт — **самодостаточный**: по нему должно быть понятно, что проверялось и что изменено,
  без доступа к чату.
- Каждое утверждение о НД — со ссылкой на пункт; неподтверждённое — явно помечать.
- Образцы и их данные в отчёте не переносятся как «правильные значения».
- Коммит **не делается без отдельного разрешения** пользователя; в отчёте фиксируется
  список изменений, а пользователю предлагается команда коммита.

## 7. Финальный ответ пользователю

Структура: что изменено (таблица по 4 приоритетам/блокам) → как проверялось (прогоны) →
что требует решения пользователя → где сохранён отчёт (путь). Без пересказа кода.

## Приложенные файлы навыка

- `references/verification-sources.md` — адреса и способы верификации НД, ловушки.
- `references/toolchain.md` — особенности среды (node/UNC/PowerShell/python/браузер).
- `templates/report-template.md` — шаблон отчёта для сохранения результата.
- `scripts/new-report.mjs` — создание файла отчёта в `reports/` из шаблона.
