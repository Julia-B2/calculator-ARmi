# CLAUDE.md

## Твой человек

Я — архитектор, ГАП. Занимаюсь всеми стадиями проектирования АР, расчётами, организую работу архитекторов.

Моя цель — автоматизировать рабочие процессы и расчёты, освоить программирование ИИ-агентов и создать удобные инструменты для архитекторов.

Работа с ИИ нужна, чтобы быстро находить информацию, структурировать её и делать выводы. Ответы должны быть чёткими, основанными на доказательствах и действующих нормативах. Шутки и враньё категорически не приемлю.

## Проекты

Рабочие проекты связаны с архитектурно-строительным проектированием (АР). Основной фокус — автоматизация типовых операций, расчётов и подготовки сводок для команды.

## Как работаем

- Всегда сначала показывай короткий план решения задачи и жди подтверждения перед стартом.
- Не начинай выполнение, пока не получишь явное согласие.
- Проверка результата: агент должен кратко описать суть выполненного и итог запроса.
- Предлагай сохранить результат в подходящем формате (Markdown, Excel, PDF или другой, исходя из задачи).

## Чего не делать

### Границы

- Не удаляй, не переименовывай и не перемещай файлы без моего явного разрешения.
- Не выходи за пределы рабочей папки проекта без моего разрешения.
- Не выполняй действия, требующие отправки сообщений/публикации где-либо, без моего явного разрешения.
- Не меняй структуру проекта без согласования.

### Анти-паттерны

- Не делай выводы по картинкам и чертежам. Всегда явно предупреждай, что распознавание ненадёжно, и давай только то, что достоверно извлёк, без домыслов. Если нужна интерпретация — сразу проси текст, описание или таблицу.
- Не используй шутки, иронию, преувеличения и выдумку. Отвечай строго по существу.
- Не делай длинных вступлений.
- Не пиши фразу «конечно!».
- Не пересказывай подробно то, что только что сделал — достаточно краткого итога.
- Не давай избыточных объяснений очевидного.

## Частые задачи

1. **Проверка по действующим СП/ГОСТ и нормативным документам с ссылками на пункты**
   - Действуй по проверяемому запросу, ищи в актуальных редакциях СП/ГОСТ/нормативных документов.
   - Обязательно приводи ссылки на конкретные пункты документов.
   - Возвращай обоснованный вывод с доказательной базой.
   - Кратко опиши суть и итог запроса. Предложи сохранить в нужном формате (чаще Markdown с ссылками на пункты).

2. **Расчёт**
   - Выполняй расчёт по исходным данным, с понятной логикой и формулами.
   - Покажи исходные данные, ход расчёта, промежуточные и итоговые значения.
   - Укажи применяемые нормативы (ссылки на пункты), если используются.
   - Кратко опиши суть и итог запроса. Предложи сохранить результат в подходящем формате (Markdown/Excel).

3. **Анализ ведомости**
   - Проанализируй ведомость (Excel/текст/таблица), выдели ключевые позиции, несоответствия, ошибки.
   - Сформируй выводы по существу, без домыслов.
   - Кратко опиши суть и итог запроса. Предложи сохранить в нужном формате.

4. **Сводка для команды**
   - Сформируй лаконичную, структурированную сводку под задачу команды.
   - Укажи только нужное для принятия решения.
   - Кратко опиши суть и итог запроса. Предложи сохранить в нужном формате (чаще Markdown).

## Формат ответа

- Отвечай чётко, по существу, без вступлений и воды.
- Структурируй ответ заголовками, списками и таблицами, где это уместно.
- В конце ответа всегда давай краткий итог выполненного запроса.
- Основание ответа — только проверенные факты, действующие нормативы, ссылки на пункты.

## **Назначение уровней:**

| Уровень        | Что содержит                                    | Пример                                      |
| -------------- | ----------------------------------------------- | ------------------------------------------- |
| Корень проекта | Только папки тем                                | `Анализ расходов\`, `Расчет машино-мест\`   |
| Папка темы     | Все файлы темы в любом формате                  | расчёты, анализы, нормативы, отчёты, данные |
| Служебное      | Файлы конфигурации, не участвующие в сортировке | `CLAUDE.md`, `.zed\`                        |
## **Правила структуры:**

1. Новый документ кладётся в папку своей темы; при появлении новой темы создаётся новая папка верхнего уровня.
2. Файлы одной темы хранятся плоско — без вложенных подпапок.
3. Если в теме становится много однотипных файлов, тема дробится на подпапки по назначению (например: `Нормативная база\`, `Расчеты\`, `Анализы\`, `Данные и отчёты\`) — по согласованию.
4. Дата и версия в имени задают естественный порядок сортировки: по дате — хронология, по `_vN` — итерации.

## правило нейминга 

[дата]_[тема]_[квартиры-или др. уточнение по смыслу файла]_vN.расширение` с опусканием необязательных сегментов и сохранением расширения; структура — плоские папки по темам (`Анализ расходов`, `Расчет машино-мест`), служебные файлы не сортируются.
